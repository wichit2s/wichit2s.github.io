SLIDE 05 · SOURCE CODE & CLEAN ARCHITECTURE INSPECTION

CODE INSPECTION CHECKLIST

5 จุดที่กรรมการเปิดดูใน GitHub Repository

  • 1. Git Commit History: มีการ Commit งานสม่ำเสมอตลอด 3 Sprints แยก Branch ชัดเจน ไม่ใช่การอัปโหลดรวดเดียวก่อนวันสอบ
  • 2. Separation of Concerns (SRP): แยก Route, Service Logic และ Database Query ออกจากกัน อ่านเข้าใจง่าย
  • 3. Error Handling & Validation: ตรวจสอบ Input ก่อนลงฐานข้อมูล ป้องกัน SQL Injection และคืน HTTP Status Code ที่ถูกต้อง
  • 4. Secret Management: ไม่ Commit ไฟล์ .env หรือรหัสผ่านฐานข้อมูลขึ้น GitHub (ใช้ .env.example แทน)
  • 5. API Documentation: มี OpenAPI/Swagger หรือ Postman Collection ให้ทีมและกรรมการทดสอบ Endpoint ได้ทันที
