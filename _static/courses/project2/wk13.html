CHAPTER 01 · PROBLEM & SCOPE

การกำหนดขอบเขตที่พัฒนาได้จริงใน 15 สัปดาห์

  • ปัญหาหลักของร้านขายของชำ (Problem Statement): จดบันทึกรายการขายด้วยมือ ทำให้ไม่ทราบต้นทุนคงคลังแบบ Real-time สินค้าหมดอายุหรือขายดีไม่ถูกแจ้งเตือนล่วงหน้า และเกิดความเสี่ยงสต็อกติดลบเมื่อคิดเงินพร้อมกัน
  • การตั้งวัตถุประสงค์แบบวัดผลได้: ใช้คำกริยาที่ตรวจสอบได้ เช่น "พัฒนาเว็บแอปพลิเคชัน POS ที่คำนวณยอดขายและตัดสต็อกอัตโนมัติ" แทนคำกว้าง ๆ อย่าง "เพื่อให้ร้านค้าทันสมัยขึ้น"
  • ขอบเขตของโครงงานปี 2 (Practiced Level): เน้นระบบ Single-branch POS ฐานข้อมูล Relational (3NF) การจัดการสต็อกและการแจ้งเตือน (ยังไม่ขยายไปสู่ AI Forecasting หรือ Microservices หลายสาขาซึ่งเป็นขอบเขตของปี 3)
CHAPTER 02 · LITERATURE & PDPA

หัวข้อทบทวนวรรณกรรมที่ต้องปรากฏใน Grocery POS

หัวข้อทบทวน ประเด็นที่ต้องวิเคราะห์เปรียบเทียบ
ซอฟต์แวร์ POS ในท้องตลาด เปรียบเทียบฟีเจอร์ ข้อจำกัด และค่าใช้จ่ายของระบบร้านค้าปลีก 2–3 ราย เพื่อยืนยันเหตุผลของการพัฒนา
Tech Stack & 3NF DB อธิบายเหตุผลในการเลือก Node.js / Python และฐานข้อมูลเชิงสัมพันธ์ที่รองรับ ACID Transaction
Agile & Scrum 3 Sprints หลักการ User Story, Acceptance Criteria และ Burndown Chart สำหรับงานทีม 1–3 คน
จริยธรรมข้อมูล (PDPA) หลักการ Data Minimization: ลบเบอร์โทรศัพท์และรหัสบัตรประชาชนลูกค้าออกจากชุดข้อมูลรายงานสรุปยอดขาย

AGILE ARTIFACTS IN CH 03

ตัวอย่าง User Story และ Acceptance Criteria

User Story: "ในฐานะพนักงานแคชเชียร์ (Cashier) ฉันต้องการสแกนบาร์โค้ดและตัดยอดสินค้าในคลังอัตโนมัติ เพื่อออกใบเสร็จและป้องกันการขายสินค้าเกินจำนวนคงเหลือ"

ACCEPTANCE CRITERIA (GIVEN-WHEN-THEN)
Given สินค้า "นมสดพาสเจอร์ไรส์ 1 ลิตร" มีคงเหลือ 3 ขวด
When แคชเชียร์กดชำระเงินจำนวน 2 ขวด
Then ระบบบันทึกคำสั่งซื้อ ลดคงเหลือเป็น 1 ขวด และสร้างแจ้งเตือนทันทีเพราะต่ำกว่า reorder_level
RISK MITIGATION IN CH 03
ความเสี่ยง: การตัดสต็อกขนานพร้อมกัน (Race Condition)

              STEP 1–2 · CLONE, INSTALL & DB MIGRATION
              
            

            
# 1. ดึงซอร์สโค้ดและติดตั้งไลบรารี
git clone https://example.com/team/grocery-pos.git
cd grocery-pos && npm ci

# 2. คัดลอกค่าเริ่มต้นและสร้างตารางฐานข้อมูล 3NF + ข้อมูลสินค้าเริ่มต้น
cp .env.example .env
psql "$DATABASE_URL" -f database/schema.sql
psql "$DATABASE_URL" -f database/seed_grocery_items.sql

          


          

            

              STEP 3–4 · BUILD, START & HEALTH CHECK
              
            

            
# 3. สร้าง Build สำหรับ Production และเริ่มการทำงาน
npm run build
npm run start

# 4. ตรวจสอบสถานะ API และการเชื่อมต่อฐานข้อมูล
curl -i http://localhost:3000/api/health
# Expected: HTTP/1.1 200 OK {"status":"ok","db":"connected"}

                  ระบบขึ้นเตือน "สินค้าคงเหลือไม่เพียงพอ"
                  สต็อกในระบบหมด หรือมีแคชเชียร์อีกเครื่องเพิ่งตัดยอดไปก่อนหน้า
                  ตรวจนับสินค้าจริงบนชั้นวาง หากมีสินค้าให้ผู้จัดการร้านปรับยอดรับเข้า (Stock Adjustment)
                

                

                  ชำระ PromptPay แล้วยังไม่ขึ้นยืนยัน
                  อินเทอร์เน็ตหน้าร้านช้า หรือยังไม่ได้กดตรวจสถานะซ้ำ
                  กดปุ่ม "ตรวจสอบสถานะการโอน" 1 ครั้ง ตรวจสอบสลิปของลูกค้า และติดต่อฝ่าย Support หากซ้ำซ้อน
                

                

                  เครื่องพิมพ์ใบเสร็จไม่ออกกระดาษ
                  กระดาษหมด ฝาเครื่องปิดไม่สนิท หรือสาย USB หลวม
                  เปิดฝาเปลี่ยนม้วนกระดาษ 58mm ปิดให้ดังคลิก แล้วสั่ง "พิมพ์ใบเสร็จย้อนหลัง" ในเมนูประวัติขาย
