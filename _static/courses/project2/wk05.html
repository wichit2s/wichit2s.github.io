SLIDE 02 / 10 · DOMAIN & USE CASES Grocery POS Domain

Grocery POS ซับซ้อนกว่าจุดขายทั่วไปอย่างไร?

ร้านขายของชำและซูเปอร์มินิมาร์ทมีสินค้าหลายพัน SKU ที่ต้องสแกนบาร์โค้ดอย่างรวดเร็ว จัดการสินค้าชั่งน้ำหนัก สินค้ามีวันหมดอายุ และมีแคชเชียร์มากกว่า 1 ช่องทางตัดสต็อกจากคลังเดียวกันในเวลาเดียวกัน

GROCERY DOMAIN CHALLENGES

4 โจทย์เฉพาะทางของร้านขายของชำ

1. Barcode & SKU Lookup ความเร็วสูง
ต้องค้นหา EAN-13 / UPC ได้ภายใน < 50ms ต่อการสแกน 1 ครั้ง
2. สินค้าชั่งน้ำหนัก & หลายหน่วยนับ
จำนวน (quantity) ต้องรองรับทศนิยม (เช่น 0.750 กก.) ไม่ใช่แค่จำนวนเต็ม
3. ล็อตสินค้าและวันหมดอายุ (Batch & Expiry)
แยกตาราง Product ออกจาก Inventory Stock เพื่อรองรับ FIFO/FEFO
4. Multi-Lane Concurrent Checkout
แคชเชียร์ 2 จุดขายสินค้าชิ้นสุดท้ายพร้อมกันต้องไม่เกิดสต็อกติดลบ

SLIDE 04 / 10 · ARCHITECTURAL DECISION Recommended for 1145 204

เลือก Modular Monolith สำหรับทีม 4–5 คน (และหลีกเลี่ยง Cyclic Dependency)

ในโครงงานปี 2 ที่มีเวลาพัฒนา 3 Sprints การแยกเป็น Microservices ตั้งแต่วันแรกเพิ่มภาระ Network, Distributed Transaction และ DevOps เกินความจำเป็น สถาปัตยกรรมที่เหมาะสมที่สุดคือ Modular Monolith ที่แบ่งขอบเขตโมดูลชัดเจนพร้อมต่อยอดเป็น Microservices ในปี 3

ARCHITECTURE COMPARISON

เปรียบเทียบ 3 รูปแบบสถาปัตยกรรม

เกณฑ์พิจารณา Spaghetti Monolith Modular Monolith Microservices
ความเร็วในการพัฒนา (3 Sprints) เร็วช่วงแรก ช้าช่วงท้าย เร็วและคุมคุณภาพได้ ช้า (Infra Overhead สูง)
ACID Transaction ข้าม Order–Stock ทำได้ (1 DB) ทำได้ทันที (1 DB) ซับซ้อน (ต้องใช้ Saga)
การทำงานเป็นทีม 4–5 คน Code ชนกันบ่อย แยก Module / PR ชัดเจน แยก Repo แต่ Debug ยาก
การขยายสู่ Cloud ปี 3 รื้อใหม่ทั้งหมด แยก Service ทีละโมดูลได้ รองรับระดับองค์กร
ACYCLIC DEPENDENCIES PRINCIPLE (ADP)

กติกาจัดวาง Dependency เป็น DAG

ตามหลักวิศวกรรมซอฟต์แวร์ (Robert C. Martin) กราฟการพึ่งพาระหว่าง Package ต้องเป็น Directed Acyclic Graph (DAG) ห้ามอ้างอิงวนกลับไปมา และใช้ Table Data Gateway (TDG) แยก Domain ออกจาก SQL:

POS Domain (Abstract) ← พึ่งพาโดยทุกโมดูล แต่ไม่พึ่งพา DB
↑ OrderGateway / ProductGateway / InventoryGateway (Interfaces)

แนวทางปฏิบัติของทีมปี 2

ห้ามเขียน SQL ใน Controller หรือ Route Handler โดยตรง ให้ผ่าน Gateway/Repository เพื่อให้เขียน Unit Test แบบ In-Memory ได้รวดเร็วไม่ต้องต่อ Database จริงทุกครั้ง
