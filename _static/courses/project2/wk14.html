SLIDE 03 // CLOUD PRODUCTION ARCHITECTURE DOCKER · PAAS · AWS / GCP

เลือกสถาปัตยกรรม Cloud Hosting ที่เหมาะกับ Grocery POS

แพลตฟอร์ม Grocery POS ประกอบด้วย 3 ส่วนหลักคือ Frontend (POS UI), Backend API (Node.js/Python) และ Relational Database (MySQL/PostgreSQL แบบ 3NF) คลิกเลือกสถาปัตยกรรมด้านล่างเพื่อดูแผนภาพการไหลและข้อควรระวังก่อนวันสอบ

เกณฑ์พิจารณา PaaS (Render / Railway) Docker + Cloud Run AWS EC2 / GCP Compute + RDS
ความเร็วในการ Deploy เร็วที่สุด (Push GitHub → Deploy) ปานกลาง (ต้องเขียน Dockerfile) ช้ากว่า (ตั้งค่า Network, Firewall, SSL เอง)
การควบคุม Environment ปานกลาง (พึ่งพา Buildpack) สูงมาก (Runtime เดียวกันทุกเครื่อง) สูงสุด (ควบคุม OS, Nginx, Ports ได้เต็มที่)
ความเสี่ยงวันสอบ Live Demo Free tier หลับ (Cold start 20–50 วินาที) Cold start ต่ำ หากตั้ง Min-instance = 1 ต้องระวัง Security Group ปิด Port หรือใบรับรอง SSL หมดอายุ
ความเหมาะสมกับทีม 1145 204 เหมาะมากสำหรับทีมที่เร่งปิดงานในสัปดาห์ที่ 14 แนะนำสูงสุด (พกพาง่าย ย้าย Cloud ได้ทันที) เหมาะกับทีมที่มีพื้นฐาน Linux / Cloud Networking แข็งแรง
SLIDE 04 // CONTAINERIZATION & ENV CONFIG PRODUCTION HYGIENE

แพ็กเกจด้วย Docker และจัดการ Environment Variables อย่างปลอดภัย

ปัญหาอันดับหนึ่งที่ทำให้ระบบพังเมื่อขึ้น Cloud คือความแตกต่างของเครื่องนักศึกษากับเซิร์ฟเวอร์ (เช่น เวอร์ชัน Node/Python, Path ไฟล์, และการ Hardcode ค่า localhost) การใช้ Docker และ .env ช่วยปิดช่องโหว่นี้ได้อย่างเด็ดขาด
