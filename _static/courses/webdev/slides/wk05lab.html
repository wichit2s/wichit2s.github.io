1.4 สร้าง Model สินค้า (Product)

Model คือคลาสในภาษา Python ที่ใช้แทนตารางในฐานข้อมูล

# chopee/models.py
from django.db import models

class Product(models.Model):
  brand = models.CharField(max_length=100) # ยี่ห้อ
  name = models.CharField(max_length=200) # ชื่อสินค้า
  price = models.DecimalField(max_digits=10, decimal_places=2) # ราคา
  year = models.IntegerField() # ปีที่ผลิต

  def __str__(self):
    return self.name

Part 2: FBVs - The Manual Way (45 min)

2.1 แสดงรายการสินค้า (Read)

เราจะใช้ Product.objects.all() เพื่อดึงสินค้าทั้งหมดมาจากฐานข้อมูล

# chopee/views.py
from .models import Product

def product_list(request):
  products = Product.objects.all() # ดึงข้อมูลทั้งหมด
  return render(request, 'list.html', {'products': products})

* ฟังก์ชัน render() จะรวม Template และข้อมูลเข้าด้วยกันเป็น HTTP Response

2.1 Template สำหรับแสดงรายการ

วนลูปแสดงผลด้วย {% for %} และเข้าถึงฟิลด์ด้วย "Dot Notation" 

<ul>
  {% for product in products %}
    <li>
      {{ product.brand }} - {{ product.name }} 
      ({{ product.price }} บาท)
    </li>
  {% empty %}
    <li>ยังไม่มีสินค้าขาย</li>
  {% endfor %}
</ul>

2.2 การเพิ่มสินค้า (Create) - HTML Part

ฟอร์มต้องระบุ method="POST" และต้องมี CSRF Token เสมอ

<form method="POST">
  {% csrf_token %} <!-- สำคัญมากเพื่อความปลอดภัย! -->
  <input type="text" name="brand" placeholder="ยี่ห้อ">
  <input type="text" name="name" placeholder="ชื่อสินค้า">
  <input type="number" name="price" step="0.01">
  <input type="number" name="year">
  <button type="submit">บันทึกสินค้า</button>
</form>

ความรู้เพิ่มเติม: CSRF คืออะไร?

Cross-Site Request Forgery (CSRF) คือการโจมตีที่ผู้ไม่หวังดีแอบส่งคำร้องขอจากเว็บไซต์อื่นในนามของคุณ

  • Django ป้องกันสิ่งนี้ด้วยการสร้าง "รหัสลับ" (Token) ฝังไว้ในฟอร์ม
  • หากไม่มี {% csrf_token %} ในฟอร์ม POST คุณจะเจอข้อผิดพลาด 403 Forbidden
  • Token นี้จะช่วยยืนยันว่าข้อมูลถูกส่งมาจากเว็บไซต์ของคุณจริงๆ

2.2 การเพิ่มสินค้า (Create) - View Part

เราจะแยกการทำงานตาม HTTP Method: GET (แสดงฟอร์ม) และ POST (บันทึกข้อมูล) 

def product_create(request):
    if request.method == 'POST':
        # ดึงค่าจากฟอร์มทีละฟิลด์ 
        brand = request.POST.get('brand')
        name = request.POST.get('name')
        price = request.POST.get('price')
        year = request.POST.get('year')
        
        # สร้างและบันทึกลง Database 
        Product.objects.create(brand=brand, name=name, price=price, year=year)
        return redirect('list')
        
    return render(request, 'create.html')

2.3 การแก้ไขข้อมูล (Update)

ในการแก้ไข เราจำเป็นต้องระบุ "ID" หรือ Primary Key (PK) ของข้อมูลชิ้นนั้นๆ เพื่อดึงข้อมูลเก่าขึ้นมาแก้ไข

1. ดึงข้อมูลชิ้นนั้น

product = get_object_or_404(Product, pk=pk)

2. แก้ไขและบันทึก

product.name = "ชื่อใหม่"
product.save()

View สำหรับ Update (Manual)

def product_update(request, pk):
    product = get_object_or_404(Product, pk=pk) # ดึงข้อมูล ถ้าไม่เจอจะแสดง 404 
    
    if request.method == 'POST':
        # ดึงค่าใหม่มาทับค่าเดิม 
        product.brand = request.POST.get('brand')
        product.name = request.POST.get('name')
        product.price = request.POST.get('price')
        product.year = request.POST.get('year')
        product.save() # บันทึกการเปลี่ยนแปลง 
        return redirect('list')
        
    return render(request, 'update.html', {'product': product})

2.4 การลบข้อมูล (Delete)

ใช้คำสั่ง delete() เพื่อลบข้อมูลชิ้นนั้นออกจากฐานข้อมูลทันที

def product_delete(request, pk):
  product = get_object_or_404(Product, pk=pk)
  product.delete() # ลบทันที!
  return redirect('list')
* คำเตือน: ในระบบจริง ควรทำหน้ายืนยันการลบ (Confirmation Page) ก่อนลบจริงเสมอ

2.5 เชื่อมต่อเส้นทาง (URLs)

ใช้ <int:pk> เพื่อส่งค่า Primary Key เข้าไปยังฟังก์ชันใน View

# mysite/urls.py หรือ chopee/urls.py
urlpatterns = [
  path('product/', views.product_list, name='list'),
  path('product/create/', views.product_create, name='create'),
  path('product/update/<int:pk>/', views.product_update, name='update'),
  path('product/delete/<int:pk>/', views.product_delete, name='delete'),
]

⚠️ ข้อควรระวังด้านความปลอดภัย!

ภัยเงียบจาก "Mass Assignment"

การดึงค่าจาก request.POST มาสร้างข้อมูลตรงๆ (เช่น Product.objects.create(**request.POST)) มีความเสี่ยงสูงมาก!

🔴 ผู้ใช้สามารถส่งข้อมูลฟิลด์อื่นๆ ที่คุณไม่ได้ตั้งใจให้แก้ไข (เช่น is_admin หรือ discount_code) ผ่านการดัดแปลง HTML Form ได้

🟢 วิธีที่ปลอดภัยคือต้องระบุฟิลด์ที่อนุญาต (Whitelist) อย่างชัดเจน หรือใช้ Django Forms ในขั้นตอนถัดไป

"นี่คือสาเหตุที่เราต้องเรียนรู้เรื่อง Django Forms ในโมดูลถัดไป!"

Part 3: FBVs - ModelForms (45 min)

ทำไมต้องใช้ ModelForm?

การเขียน HTML Form เองนั้นน่าเบื่อและเสี่ยงต่อข้อผิดพลาด (เช่น พิมพ์ชื่อฟิลด์ผิด) Django จึงสร้าง "สะพาน" เชื่อมระหว่าง Model และ Form ให้เรา

เร็ว (Speed)

สร้างฟอร์มที่ซับซ้อนได้ในไม่กี่บรรทัด

แม่นยำ (Consistency)

กฎการตรวจสอบ (Validation) จะตรงตาม Model เสมอ

ปลอดภัย (Security)

มีระบบ Whitelist ป้องกัน Mass Assignment

เปรียบเทียบ: Manual Form vs ModelForm

หัวข้อ Manual Form ModelForm
การนิยามฟิลด์ ต้องเขียนชื่อฟิลด์ซ้ำจาก Model สร้างจาก Model อัตโนมัติ
การตรวจสอบข้อมูล ต้องเขียน Logic เช็คเอง ดึงข้อจำกัดมาจาก Model ทันที
การบันทึกข้อมูล ต้องดึงค่ามา Map ใส่ Object เอง ใช้คำสั่ง .save() สั้นๆ

Step 3.1: สร้างไฟล์ forms.py

ใช้คลาส Meta ภายในเพื่อระบุ Model และฟิลด์ที่ต้องการ

# chopee/forms.py
from django import forms
from .models import Product

class ProductForm(forms.ModelForm):
  class Meta:
    model = Product
    fields = ['brand', 'name', 'price', 'year'] # Whitelist ฟิลด์

ความรู้เพิ่มเติม: การเลือกฟิลด์

ใน Meta เราสามารถกำหนดฟิลด์ได้หลายรูปแบบ :

  • fields = '__all__' ใช้ทุกฟิลด์ที่มีใน Model (ไม่ค่อยแนะนำในแง่ความปลอดภัย)
  • fields = ['name', 'price'] ระบุเฉพาะฟิลด์ที่อนุญาต (Whitelist) - วิธีที่ปลอดภัยที่สุด!
  • exclude = ['secret_key'] ระบุฟิลด์ที่ "ห้าม" นำมาสร้างฟอร์ม (Blacklist)

Step 3.2: View สำหรับสร้างสินค้า (Refactored)

def product_create(request):
    # Binding data: ถ้าเป็น POST ให้เอาค่าจาก request มาใส่ในฟอร์ม 
    form = ProductForm(request.POST or None)
    
    if request.method == 'POST':
        if form.is_valid(): # ตรวจสอบความถูกต้องอัตโนมัติ 
            form.save() # บันทึกลง DB ทันที 
            return redirect('list')
            
    return render(request, 'form.html', {'form': form})

เจาะลึก: สถานะของฟอร์ม

1. Unbound Form

"ฟอร์มที่ยังไม่มีข้อมูลผูกติด"

  • มักเกิดจากคำขอแบบ GET
  • แสดงหน้าฟอร์มเปล่าหรือค่าเริ่มต้น
  • is_bound จะเป็น False

2. Bound Form

"ฟอร์มที่มีข้อมูลผูกติดแล้ว"

  • มักเกิดจากคำขอแบบ POST
  • สามารถสั่ง is_valid() เพื่อรันการตรวจสอบได้
  • ถ้าข้อมูลผิด จะแสดง Error พร้อมค่าเดิมที่กรอกมา

Step 3.3: การแสดงผลใน Template

ใช้ {{ form.as_p }} เพื่อสร้าง HTMLMarkup อัตโนมัติ

<form method="POST">
  {% csrf_token %}
  {{ form.as_p }} <!-- แสดงฟอร์มในรูปแบบย่อหน้า <p> -->
  <button type="submit">ตกลง</button>
</form>
* หมายเหตุ: คุณยังสามารถใช้ .as_table หรือ .as_ul ได้เช่นกัน

Step 3.4: View สำหรับแก้ไข (Update)

หัวใจสำคัญคือการส่ง instance เข้าไปเพื่อให้ Django รู้ว่าต้องแก้ไขข้อมูลชิ้นไหน 

def product_update(request, pk):
    product = get_object_or_404(Product, pk=pk)
    
    # ระบุ instance=product เพื่อดึงข้อมูลเก่ามาใส่ในฟอร์ม 
    form = ProductForm(request.POST or None, instance=product)
    
    if request.method == 'POST':
        if form.is_valid():
            form.save() # Django จะทำการ UPDATE แถวเดิมใน DB ให้เอง
            return redirect('list')
            
    return render(request, 'form.html', {'form': form})

Advanced: save(commit=False)

บางครั้งเราต้องการแก้ไขข้อมูล "ก่อน" บันทึกลงฐานข้อมูลจริง (เช่น ใส่ชื่อผู้สร้างแอปอัตโนมัติ)

obj = form.save(commit=False)
obj.created_by = request.user
obj.save()

การใช้ commit=False จะสร้าง Python Object ขึ้นมาใน Memory โดยที่ยังไม่บันทึกลงฐานข้อมูล ทำให้เรามีโอกาส "แทรกแทรง" ข้อมูลได้

Part 4: Class-Based Views (45 min)

ทำไมต้องใช้ Class-Based Views?

Class-based generic views ถูกสร้างขึ้นเพื่อจัดการงานที่พบบ่อย (Common Tasks) โดยใช้แนวคิด Object-Oriented เพื่อให้ขยายขีดความสามารถได้ง่ายกว่าการใช้ฟังก์ชันเพียงอย่างเดียว

1. มาตรฐาน (Generic Patterns)

Django มี Template สำเร็จรูปสำหรับแสดงรายการ (List), รายละเอียด (Detail), และการแก้ไขข้อมูล (Edit)

2. ลดโค้ดซ้ำซ้อน (DRY)

ไม่ต้องเขียน `if request.method == 'POST'` ซ้ำๆ เพราะคลาสจะแยกการทำงานผ่าน method ภายในให้อัตโนมัติ

4.1 การแสดงรายการด้วย ListView

ListView จะดึงข้อมูล QuerySet และส่งไปยัง Template ให้อัตโนมัติ

from django.views.generic import ListView
from .models import Product

class ProductListView(ListView):
  model = Product
  # ข้อมูลจะถูกส่งไปยัง Template ในชื่อ 'object_list' หรือ 'product_list'
ข้อตกลงเบื้องต้น: หากไม่ระบุชื่อไฟล์ Django จะมองหา `chopee/product_list.html`

กฎการตั้งชื่อ Template (Naming Conventions)

Display Views

  • ListView: <model>_list.html
  • DetailView: <model>_detail.html

Editing Views

  • Create/Update: <model>_form.html
  • Delete: <model>_confirm_delete.html

การทำตามกฎนี้จะช่วยลดโค้ดใน View ได้มหาศาล เพราะไม่ต้องระบุ template_name ทีละตัว

4.2 การจัดการฟอร์ม (Create & Update)

// views.py

class ProductCreateView(CreateView):
    model = Product
    fields = ['brand', 'name', 'price']
    success_url = reverse_lazy('list')

class ProductUpdateView(UpdateView):
    model = Product
    fields = ['brand', 'name', 'price']
    success_url = reverse_lazy('list')

จุดเด่นที่น่าสนใจ:

  • ✓ Auto-ModelForm: Django สร้าง Form จากโมเดลและฟิลด์ที่ระบุให้อัตโนมัติ
  • ✓ Single Template: ทั้งการเพิ่มและแก้ไขสามารถแชร์ไฟล์ product_form.html ร่วมกันได้
  • ✓ reverse_lazy: ใช้สำหรับระบุเส้นทางหลังจากบันทึกเสร็จสิ้น

4.3 การลบพร้อมการยืนยัน (DeleteView)

DeleteView มีระบบความปลอดภัยที่ต้องยืนยันตัวตนผ่านหน้า HTML ก่อนการลบจริง

class ProductDeleteView(DeleteView):
  model = Product
  success_url = reverse_lazy('list')
  # แสดงหน้า ยืนยัน ใน GET และลบข้อมูลใน POST
Minimal Template (product_confirm_delete.html):
<form method="post">{% csrf_token %}
  คุณแน่ใจหรือไม่ว่าจะลบ "{{ object }}"?
  <button type="submit">ยืนยันการลบ</button>
</form>

4.4 เชื่อมต่อเส้นทาง (URLconf)

เนื่องจาก URL Resolver ต้องการฟังก์ชัน เราจึงต้องใช้ .as_view() แปลงคลาสเป็นฟังก์ชัน

# chopee/urls.py
urlpatterns = [
  path('', views.ProductListView.as_view(), name='list'),
  path('product/create/', views.ProductCreateView.as_view(), name='create'),
  path('product/update/<int:pk>/', views.ProductUpdateView.as_view(), name='update'),
  path('product/delete/<int:pk>/', views.ProductDeleteView.as_view(), name='delete'),
]
* หมายเหตุ: CBV จะคาดหวังให้เราส่ง Primary Key ผ่าน URL ในชื่อ <int:pk> เสมอ

ความรู้เพิ่มเติม: การเพิ่มข้อมูลไปยัง Template

หากต้องการส่งข้อมูลพิเศษ (Extra Context) เข้าไปยัง Template ใน CBV เราจะทำการ override เมธอด get_context_data 

def get_context_data(self, **kwargs):
    # 1. เรียกใช้งานข้อมูลเดิมจากคลาสแม่
    context = super().get_context_data(**kwargs)
    # 2. เพิ่มข้อมูลใหม่ที่ต้องการ
    context['extra_info'] = "ข้อมูลพิเศษสำหรับคุณ"
    # 3. ส่งข้อมูลทั้งหมดกลับไป
    return context

การใช้ Mixins ในการเสริมพลัง

Mixins คือเครื่องมือในการดึงความสามารถจากหลายคลาสมารวมกัน เช่น การเช็คสิทธิ์การเข้าใช้งาน

LoginRequiredMixin

ใช้ป้องกันไม่ให้ผู้ที่ไม่ล็อคอินเข้าถึง View ได้ โดยต้องวางไว้ด้านซ้ายสุดเสมอ

PermissionRequiredMixin

ใช้สำหรับเช็คสิทธิ์เฉพาะทางก่อนรัน View
