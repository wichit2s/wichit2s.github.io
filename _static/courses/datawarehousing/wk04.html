Phase 1: Advanced Dimensional Design

วิเคราะห์และเลือกใช้ SCD ประเภทต่างๆ (Type 1, 2, 3) ได้ตามความต้องการธุรกิจ

Slowly Changing Dimensions (SCD)

คือเทคนิคการจัดการมิติที่มีการเปลี่ยนแปลงค่าของแอตทริบิวต์เมื่อเวลาผ่านไป

ทำไมต้องทำ SCD?

  • • เพื่อรักษาความถูกต้องของการรายงานผลย้อนหลัง
  • • เพื่อติดตามพฤติกรรมลูกค้าที่เปลี่ยนแปลง (เช่น การย้ายที่อยู่)
  • • เพื่อให้ AI เอเจนต์เข้าใจบริบทของข้อมูล ณ ช่วงเวลานั้นๆ อย่างแม่นยำ

ภารกิจ: เลือก SCD ให้โครงการ E-Commerce

โจทย์: จงระบุว่าสถานการณ์ต่อไปนี้ควรใช้ SCD ประเภทใด?

1. พนักงานสะกดชื่อยี่ห้อสินค้าผิดจาก "Appel" เป็น "Apple"
2. ลูกค้า VIP ย้ายที่อยู่จากกรุงเทพฯ ไปภูเก็ต และเราต้องการให้ยอดขายเก่าแสดงที่กรุงเทพฯ ส่วนยอดใหม่แสดงที่ภูเก็ต
3. ฝ่ายการตลาดต้องการดูยอดขายรวมปีนี้เทียบกับเขตการขายเก่าของปีที่แล้วในรายงานเดียว

เฉลยขั้นตอนการแก้ปัญหา SCD

Type 1

**แก้คำผิด:** เพราะข้อมูลเดิมผิดพลาดทางเทคนิค ไม่ใช่การเปลี่ยนแปลงทางธุรกิจ

Type 2

**ย้ายที่อยู่:** เพื่อ "Partition History" ให้ยอดขายเก่าและใหม่ผูกกับสถานที่ที่ถูกต้อง ณ เวลานั้น

Type 3

**เทียบเขตเก่า/ใหม่:** เพื่อสร้าง "Alternate Realities" ให้วิเคราะห์เปรียบเทียบในแถวเดียวกันได้

Degenerate Dimensions (มิติเสื่อม)

"มิติที่ไม่มีตารางเป็นของตัวเอง แต่อยู่ในตาราง Fact"

ตัวอย่าง:

  • • เลขที่คำสั่งซื้อ (Order Number)
  • • เลขที่ใบกำกับภาษี (Invoice ID)
  • • รหัสพัสดุ (Tracking Number)

ทำไมต้องทำ?

  • • ลดการ Join ตารางที่ไม่จำเป็น
  • • ข้อมูลเหล่านี้มักไม่มีคุณลักษณะอื่น (Attributes) ให้เก็บ

ออกแบบ Junk Dimension

ภารกิจ Phase 1 (ต่อ):

ในโครงการ E-Commerce ของคุณ มีแฟล็ก 3 ตัวดังนี้:

  • 1. **Payment_Status** (Paid, Pending)
  • 2. **Delivery_Type** (Standard, Express)
  • 3. **Is_Gift** (Yes, No)

คำถาม:

1. จงระบุจำนวนแถวทั้งหมดที่อาจเกิดขึ้นใน Junk Dimension นี้ (Cross Join)

2. วาดโครงสร้างตาราง Junk Dimension เบื้องต้น

เฉลยขั้นตอนการสร้าง Junk Dimension

1. การคำนวณขนาดตาราง:

2 (Payment) x 2 (Delivery) x 2 (Gift) = **8 แถว**

"ตาราง Junk จะเก็บทุกความเป็นไปได้ของการรวมกันของ Flags"

SCD ในยุคของ AI Agents

AI เอเจนต์สมัยใหม่ (เช่น AV-SQL) มีบทบาทสำคัญในการจัดการ SCD:

  • Auto-Detection
    ตรวจจับ Schema Drift หรือการเปลี่ยนแปลงของมิติต้นทางอัตโนมัติ
  • Agentic Mapping
    AI ช่วยเขียน SQL สำหรับการสร้าง SCD Type 2 ที่ซับซ้อนได้แม่นยำขึ้น
  • Semantic Stability
    ช่วยให้ Semantic Layer คงความถูกต้องแม้ข้อมูลประวัติจะเปลี่ยนไป

บทสรุปสัปดาห์ที่ 4

1. **SCD Type 2** คือวิธีหลักในการเก็บประวัติข้อมูลในคลังข้อมูลสมัยใหม่
2. **Degenerate Dimensions** ช่วยลดความซับซ้อนโดยการเก็บรหัสเอกสารไว้ใน Fact
3. **Junk Dimensions** ทำให้โมเดลสะอาดขึ้นโดยการรวมกลุ่ม Flags
