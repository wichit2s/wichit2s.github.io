แผนการจัดกิจกรรมการเรียนรู้แบบเน้นการปฏิบัติ (Active Learning) ระยะเวลา 5 สัปดาห์ (สัปดาห์ละ 3 ชั่วโมง รวม 15 ชั่วโมง) หลังสอบกลางภาค เพื่อพัฒนา **Compass Application** โดยใช้ **Django REST Framework (DRF)** เป็น Backend และ **Flutter** เป็น Frontend ตามโครงสร้างสถาปัตยกรรมแบบ **MVVM** ของ Google:

---

### **สัปดาห์ที่ 1: การทบทวนเนื้อหาก่อนกลางภาค และการทำความเข้าใจสถาปัตยกรรม Compass App**
**วัตถุประสงค์:** ทบทวนพื้นฐาน Flutter และเข้าใจโครงสร้างสถาปัตยกรรมแบบ MVVM (Model-View-ViewModel) รวมถึงแนวคิดการแบ่งส่วนการทำงาน (Separation of Concerns) ของแอปพลิเคชัน Compass

*   **ชั่วโมงที่ 1: ทบทวนความรู้ก่อนกลางภาค (ปฏิบัติ)**
    *   ทบทวนและทำแบบทดสอบเชิงปฏิบัติสั้น ๆ เกี่ยวกับการใช้ **Stateless/Stateful Widgets**, การจัด Layout, และการเขียนฟังก์ชันจัดการสถานะพื้นฐานด้วย `setState`
    *   ทบทวนแนวคิด **UI is a function of state** (หน้าจอแอปพลิเคชันถูกวาดขึ้นมาตามสถานะของข้อมูล)
*   **ชั่วโมงที่ 2: เจาะลึกโครงสร้างโฟลเดอร์สถาปัตยกรรม Compass App (ปฏิบัติ)**
    *   สำรวจและวิเคราะห์โค้ดตัวอย่างจาก [Compass App Github Repository](https://github.com/flutter/samples/tree/main/compass_app)
    *   ทำความเข้าใจโครงสร้างโฟลเดอร์แบ่งตามสถาปัตยกรรม:
        *   `lib/data/` (Repositories & Services)
        *   `lib/domain/` (Domain Models)
        *   `lib/ui/` (Views & ViewModels แบ่งตามฟีเจอร์)
    *   เรียนรู้กฎการเชื่อมโยงข้อมูลระหว่างเลเยอร์ (Rules of Engagement): **View ↔ ViewModel ↔ Repository ↔ Service**
*   **ชั่วโมงที่ 3: ตั้งค่าระบบและเตรียมเครื่องมือในการทำงาน (ปฏิบัติ)**
    *   สร้างโปรเจกต์ Flutter ใหม่ และจัดโครงสร้างโฟลเดอร์ตามสถาปัตยกรรมของ Compass App
    *   ติดตั้งเครื่องมือและทดสอบรันแอปพลิเคชันเวอร์ชันเปล่าบน Emulator หรืออุปกรณ์จริง

### **สัปดาห์ที่ 2: พัฒนา REST API Backend ด้วย Django REST Framework & JWT Authentication**
**วัตถุประสงค์:** สร้างระบบดึงข้อมูลทริปการเดินทาง (Itinerary/Booking) และออกแบบระบบยืนยันตัวตนแบบไร้สถานะ (Stateless Authentication) โดยใช้ระบบ Token ร่วมกับ DRF

*   **ชั่วโมงที่ 1: การออกแบบฐานข้อมูล และการสร้าง REST API เบื้องต้น (ปฏิบัติ)**
    *   ทำความคุ้นเคยกับโมเดลข้อมูลใน Compass App เช่น `User` และ `Booking`
    *   เขียนโค้ด Django Models และ Serializers เพื่อแปลงโมเดลข้อมูลให้เป็นไฟล์ JSON
    *   สร้าง Endpoint API สำหรับดึงข้อมูลรายการทริป (GET) และบันทึก/ลบทริป (POST, DELETE)
*   **ชั่วโมงที่ 2: ติดตั้งและตั้งค่า JWT Authentication (ปฏิบัติ)**
    *   ติดตั้งแพ็กเกจ `djangorestframework-simplejwt`
    *   กำหนดค่าใน `settings.py` เพื่อให้ DRF ตรวจสอบ Token ใน HTTP Authorization Header
    *   เพิ่มเส้นทาง URL (Routes) สำหรับการเข้าสู่ระบบเพื่อขอรับ Access Token และ Refresh Token
*   **ชั่วโมงที่ 3: ระบบรักษาความปลอดภัยและการทดสอบ API (ปฏิบัติ)**
    *   ใช้คลาสสิทธิ์การเข้าถึง `IsAuthenticated` เพื่อป้องกัน Endpoint ทริปการเดินทางจากการเข้าถึงโดยไม่ระบุตัวตน
    *   ตั้งค่าอายุการใช้งานของ Token (เช่น Access Token 15 นาที และ Refresh Token 1 วัน) เพื่อลดความเสี่ยงจากการถูกขโมย Token
    *   ใช้โปรแกรมทดสอบ API (เช่น Postman หรือ cURL) ในการทดสอบเข้าสู่ระบบเพื่อรับ Token, การใช้ Refresh Token เพื่อขอรหัสยืนยันตัวตนรอบใหม่

### **สัปดาห์ที่ 3: พัฒนา Flutter Data Layer (Services & Repositories)**
**วัตถุประสงค์:** พัฒนาส่วนดึงข้อมูลเบื้องหลังแอปพลิเคชัน (Data Layer) เพื่อทำการเชื่อมต่อ สื่อสาร และจัดเก็บ Token ยืนยันตัวตนร่วมกับ DRF Backend

*   **ชั่วโมงที่ 1: พัฒนาเลเยอร์ Service (Stateless API Client) (ปฏิบัติ)**
    *   สร้างคลาส **Service** (เช่น `ApiClient`) ซึ่งมีบทบาทเดียวคือเชื่อมต่อและดึงข้อมูลดิบจาก API Backend (DRF HTTP Client)
    *   เขียนฟังก์ชันเรียกเข้าสู่ระบบ, ดึงรายชื่อทริป (`getBookings`), และลบทริป (`deleteBooking`)
    *   ออกแบบระบบจัดการข้อผิดพลาดและส่งข้อมูลออกไปเป็นคลาสผลลัพธ์ครอบคลุมอย่างปลอดภัย
*   **ชั่วโมงที่ 2: พัฒนาเลเยอร์ Repository (Single Source of Truth) (ปฏิบัติ)**
    *   สร้างคลาส **Repository** (เช่น `BookingRepository`, `UserRepository`) เพื่อควบคุมการเข้าถึงและการเปลี่ยนแปลงข้อมูลของทริปทั้งหมด
    *   เขียนฟังก์ชันเพื่อดึงข้อมูลดิบผ่าน `ApiClient` แปลงไฟล์ข้อมูล JSON ให้เป็นรูปแบบโมเดลตามขอบเขตงานจริง (Domain Models) และส่งต่อให้ ViewModel
    *   เขียนระบบกักเก็บการเปลี่ยนแปลงข้อมูล (Caching) ของทริปเพื่อแสดงผลทันที
*   **ชั่วโมงที่ 3: การจัดการ Token ในแอปพลิเคชัน (ปฏิบัติ)**
    *   สร้างระบบจัดเก็บข้อมูลแบบถาวรบนอุปกรณ์ในแอป Flutter สำหรับความปลอดภัยของ JWT
    *   เขียน HTTP Interceptor ร่วมกับเลเยอร์เน็ตเวิร์ก เพื่อดักจับข้อผิดพลาด 401 Unauthorized และส่งส่งคำขอ Refresh Token อัตโนมัติเบื้องหลังโดยที่ผู้ใช้งานไม่ต้องเข้าสู่ระบบใหม่ซ้ำซ้อน

### **สัปดาห์ที่ 4: พัฒนา Flutter UI Layer (ViewModels, Views & Command Pattern)**
**วัตถุประสงค์:** ทำความเข้าใจและออกแบบหน้าจอแสดงผล (Views) และตรรกะเบื้องหลังหน้าจอ (ViewModels) ตามโครงสร้างสถาปัตยกรรม MVVM และการใช้รูปแบบคำสั่งจัดการคำขอ (Command Pattern)

*   **ชั่วโมงที่ 1: ออกแบบและพัฒนา ViewModel ร่วมกับ ChangeNotifier (ปฏิบัติ)**
    *   สร้างคลาส `HomeViewModel` โดยขยายคลาสจาก **`ChangeNotifier`**
    *   นำเข้าคลาส `BookingRepository` และ `UserRepository` เข้ามาเป็นตัวแปรแบบเป็นส่วนตัว (Private) เพื่อป้องไม่ให้เลเยอร์ View เข้าถึงฐานข้อมูลได้โดยตรง
    *   ประกาศตัวแปรจัดเก็บข้อมูลผู้ใช้งานและรายการจอง (`User`, `List<BookingSummary>`) และเรียกใช้คำสั่ง **`notifyListeners()`** เพื่อส่งสัญญาณรีโหลดเมื่อมีการดึงข้อมูลเสร็จสิ้นหรือมีการลบข้อมูลเกิดขึ้น
*   **ชั่วโมงที่ 2: ออกแบบการโหลดและแสดงผลผ่าน Command Objects (ปฏิบัติ)**
    *   สร้างคลาส **`Command`** เพื่อเป็นตัวครอบกระบวนการทำงานแบบอะซิงโครนัส (Asynchronous) ทำหน้าที่จัดลำดับสถานะการเรียกทำงาน (running, completed, error)
    *   ประกาศคำสั่งใช้งานใน ViewModel เช่น `load` เพื่อดึงข้อมูลทริปมาแสดงผล และ `deleteBooking` เพื่อจัดการลบทริป
*   **ชั่วโมงที่ 3: พัฒนา View (Stateless Widgets) และการรีเฟรชเฉพาะส่วนด้วย ListenableBuilder (ปฏิบัติ)**
    *   เขียนโค้ดหน้าจอ `HomeScreen` ให้เป็นคลาส `StatelessWidget` เพื่อประหยัดการทำงานของหน่วยความจำและแยกการคำนวณทางลอจิกออกจากหน้าจอทั้งหมด
    *   ใช้ **`ListenableBuilder`** ตรวจจับสถานะการเปลี่ยนแปลงของ ViewModel เพื่อรีโหลดเนื้อหาเฉพาะจุด
    *   ใช้คำสั่งตรวจสอบสถานะของคลาสคำสั่ง `viewModel.load.running` เพื่อสร้างหน้าจอแสดงไอคอนโหลดข้อมูล (`CircularProgressIndicator`) หรือแสดงหน้าจอข้อผิดพลาดกรณีดึงข้อมูลไม่สำเร็จแบบไดนามิก

### **สัปดาห์ที่ 5: การพึ่งพากันผ่านระบบ Dependency Injection, การเขียนเทสแบบควบคุม และนำเสนอโครงงาน**
**วัตถุประสงค์:** ประกอบทุกเลเยอร์ของแอปพลิเคชันเข้าด้วยกัน เขียนการจำลองฟังก์ชันเพื่อตรวจสอบความปลอดภัยของระบบ และนำเสนอผลงานจริง

*   **ชั่วโมงที่ 1: การต่อวงจรผ่านรูปแบบ Dependency Injection (DI) (ปฏิบัติ)**
    *   เขียนโค้ดผูกความต้องการใช้งานส่วนต่าง ๆ ในเลเยอร์สูงสุดผ่าน **`MultiProvider`** ของแพ็กเกจ `provider`
    *   กำหนดให้ส่งตัวแปร `ApiClient` เข้าไปในคอนสตรักเตอร์ของ `BookingRepositoryRemote` และนำ `BookingRepositoryRemote` ที่สร้างเสร็จฉีดต่อเข้าสู่ View Model ต่าง ๆ ผ่าน Context
    *   ทดสอบระบบการล็อคอิน, การเรียกแสดงข้อมูล และทดลองสไลด์ลบข้อมูลทริปบนแอปพลิเคชันที่ดึงข้อมูลจาก DRF Backend ตัวจริง
*   **ชั่วโมงที่ 2: ปฏิบัติการจำลองสถานะเพื่อเขียนระบบการตรวจสอบคุณภาพ (Testing) (ปฏิบัติ)**
    *   ทำความเข้าใจแนวคิดการสร้างสภาพแวดล้อมเลียนแบบระบบการดึงข้อมูลเพื่อทดสอบ View Model
    *   เขียนโค้ดจำลองข้อมูลคลังเก็บอย่างง่าย เช่น `FakeBookingRepository` และ `FakeUserRepository`
    *   ทดสอบความเสถียรของแอปพลิเคชันด้วยการส่งข้อมูลปลอมเข้าสู่ View Model เพื่อวิเคราะห์สิทธิ์การแสดงผลโดยไม่ต้องเชื่อมต่อข้อมูลเน็ตเวิร์กของ API จริง
*   **ชั่วโมงที่ 3: นำเสนอโครงงาน Compass Application (ปฏิบัติ)**
    *   นำเสนอและวิพากษ์วิธีการแก้ปัญหาทางสถาปัตยกรรมแบบกลุ่ม
    *   สาธิตการเชื่อมต่อรับส่งข้อมูลระหว่าง Flutter และ DRF Backend แบบสด ๆ
    *   สรุปผลการจัดสถาปัตยกรรมแบบ MVVM จากการทดลองใช้งานจริง
